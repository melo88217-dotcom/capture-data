# 多 Agent 协作协议

## 线程设置

推荐创建三个 Codex 对话：

1. `项目总控 / Agent Coordinator`
2. `产品规划 Agent / Product Planning Agent`
3. `产品开发 Agent / Product Development Agent`

用户主要和 `项目总控` 对话。主控负责跨会话发任务、收结果和组织确认。

## 标准阶段

### 1. 需求输入

用户给出产品想法后，主控先整理：
- 产品目标
- 目标用户
- 核心场景
- 技术偏好
- 部署和数据要求
- 明确的限制条件

### 2. 产品规划

主控把需求发给产品规划 Agent。

规划 Agent 输出：
- 产品定位
- MVP 功能清单
- 非 MVP 功能清单
- 页面 / 模块结构
- 用户流程
- 数据模型建议
- 开发优先级
- 验收标准

产物写入：
- `docs/prd.md`
- `docs/acceptance-criteria.md`

### 3. 用户确认

主控把 PRD 和验收标准汇总给用户确认。

未经用户确认，不进入开发阶段。

### 4. 开发实现

主控把已确认的 PRD 和验收标准发给产品开发 Agent。

开发 Agent 输出：
- 已完成内容
- 改动文件
- 运行方式
- 测试结果
- 已知限制

产物写入：
- `docs/dev-notes.md`

### 5. 产品验收

主控把开发结果发给产品规划 Agent 验收。

规划 Agent 输出：
- 验收结论：通过 / 不通过
- 每条验收标准状态
- 发现的问题
- 必须返工项
- 可选优化项

产物写入：
- `docs/qa-report.md`

### 6. 返工闭环

如果验收不通过：
1. 主控把返工清单发给开发 Agent。
2. 开发 Agent 修改并更新开发说明。
3. 主控再次发给规划 Agent 复验。
4. 循环直到通过，或出现需要用户决策的问题。

## 跨会话消息模板

### 发给产品规划 Agent

```text
你是产品规划 Agent。请基于以下产品想法输出可执行规划。

产品想法：
...

请产出：
1. 产品定位
2. 目标用户
3. 核心场景
4. MVP 功能清单
5. 非 MVP 功能清单
6. 页面 / 模块结构
7. 用户流程
8. 数据模型建议
9. 开发优先级
10. 明确的验收标准

要求：
- 不写空泛愿景
- 每个功能都要可开发、可验收
- 验收标准必须能被开发 Agent 和验收 Agent 使用
- 把结果写入 docs/prd.md 和 docs/acceptance-criteria.md
```

### 发给产品开发 Agent

```text
你是产品开发 Agent。请根据已确认的 PRD 和验收标准实现项目。

PRD：
见 docs/prd.md

验收标准：
见 docs/acceptance-criteria.md

请完成：
1. 创建或修改项目代码
2. 实现 MVP 功能
3. 补充必要测试
4. 启动本地服务或说明运行方式
5. 输出实现摘要、改动文件、测试结果、已知限制

要求：
- 不擅自扩大范围
- 遇到需求歧义时以 PRD 优先级为准
- 把开发说明写入 docs/dev-notes.md
- 不直接 push GitHub
```

### 发给产品规划 Agent 验收

```text
你现在作为验收 Agent。请根据已确认的 PRD 和验收标准，对开发结果进行验收。

PRD：
见 docs/prd.md

验收标准：
见 docs/acceptance-criteria.md

开发说明：
见 docs/dev-notes.md

请输出：
1. 验收结论：通过 / 不通过
2. 每条验收标准状态
3. 发现的问题
4. 必须返工项
5. 可选优化项
6. 给开发 Agent 的明确修改指令

要求：
- 只按已确认 PRD 验收
- 不临时增加新需求
- 把验收报告写入 docs/qa-report.md
```
