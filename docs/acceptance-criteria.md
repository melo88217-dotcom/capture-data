# 第一版验收标准

## 功能验收

- 可以添加抖音、视频号对标账号。
- 新增账号时可以填写账号名称、主页链接、分类、标签、备注。
- 每个账号可以设置采集周期：每日、每周、仅手动。
- 新增账号默认采集周期为每日。
- 账号列表可以展示平台、采集周期、最新粉丝量、最近采集状态、最近采集时间。
- 用户可以点击“立即更新”触发一次采集任务。
- 系统可以生成采集任务，并记录任务状态。
- 采集任务支持状态：待执行、执行中、成功、部分成功、失败、跳过。
- 成功采集后写入账号粉丝量快照。
- 成功采集后写入视频点赞量、评论数、收藏数快照。
- 平台不公开字段时显示“平台未公开”，不按失败处理。
- 采集失败时不覆盖上一次成功数据。
- 周汇总可以展示粉丝新增、点赞新增、评论新增、收藏新增。
- 数据不足时显示“数据不足”，不强行推断。

## 页面验收

- 首页可以看到账号数量、本周采集、采集失败、粉丝新增、互动新增。
- 对标账号页可以查看账号列表并触发立即更新。
- 视频数据页可以查看已采集视频指标。
- 采集任务页可以查看任务状态和失败原因。
- 周汇总页可以查看账号维度的每周变化。
- 设置页可以看到数据库位置、访问范围和采集边界说明。
- 页面在 1440px 桌面宽度下没有明显错位、遮挡或白屏。
- 页面在移动宽度下可正常滚动和使用核心操作。

## 数据和状态验收

- `available` 表示字段已采集。
- `not_public` 表示页面可访问但平台未公开字段。
- `failed` 表示采集失败。
- `insufficient` 表示周汇总数据不足。
- 缺失值不按 0 参与增长计算。
- 快照数据只追加，不默认覆盖历史。
- 同一账号同一时间不重复创建待执行或执行中的采集任务。

## 合规验收

- 不采集非公开数据。
- 不绕过登录、验证码、风控、权限限制。
- 不采集评论正文。
- 不采集评论用户信息。
- 不采集粉丝列表。
- 不采集私信。
- 不下载视频文件。
- 遇到登录、验证码、权限限制时记录失败原因并停止。

## 本地运行验收

- `npm install` 可以安装依赖。
- `npm run build` 可以成功构建前端。
- `npm audit --omit=dev` 无已知生产依赖漏洞。
- `npm run dev` 可以启动本地服务。
- 前端地址由 `.env.development` 的 `FRONTEND_PORT` 决定；当前项目分配为 `http://127.0.0.1:3102/`。
- API 地址由 `.env.development` 的 `BACKEND_PORT` 决定；当前项目分配为 `http://127.0.0.1:8102/`。
- `GET /api/health` 返回 `ok: true` 和 SQLite 数据库路径。
- SQLite 数据文件保存在 `data/app.sqlite`。
- 日志文件保存在 `logs/`。

## GitHub 发布前验收

发布或 push 前必须先执行隐私检查，并把结果告诉用户，等待用户确认后再 push。

必须确认：

- `.env` 不提交。
- 本地 SQLite 数据库不提交。
- `logs/` 不提交。
- 缓存、上传、导出、备份文件不提交。
- 代码中没有硬编码 API key、token、cookie、密码、私钥。
- `.env.example` 只保留示例值。
