# 账号主页指标与置顶作品过滤改造计划

## 目标与验收

1. 抖音账号主页采集同时识别公开的粉丝量和获赞总量，并在概览账号表展示两列。
2. 采集账号作品时，任何带有“置顶”标记的作品不入库、不计入本次采集数。
3. 已有账号、快照与非置顶作品采集行为保持兼容；无法公开读取的指标明确标记，而非伪造数值。

## 交付物

- 数据库与 API：账号获赞总量的最新值与快照持久化。
- 采集器：从主页头部读取粉丝和获赞，识别并跳过置顶作品卡片。
- 概览：账号表新增“获赞量”列。
- 回归测试：覆盖指标解析/持久化以及置顶过滤。

## 执行阶段

1. 盘点当前 schema、采集器、仓储层和概览数据合同。
2. 以最小迁移扩展数据模型，并让采集结果贯穿入库和 API。
3. 在作品卡片提取前识别置顶状态并过滤；为页面文本与 DOM 结构变化保留稳健判断。
4. 更新概览页面，运行单元测试、构建和本地接口验证。

## 技术决策与风险

- 只读取账号公开主页中已展示的数据，不绕过登录、验证码或风控。
- 置顶由作品卡片自身或紧邻文本的明确“置顶”标签判定，不能仅靠标题文字，避免误伤正常标题。
- 主页 DOM 是易变外部界面；解析失败应保留 `not_public`/`unknown` 状态，不影响其他可采字段。

- 已完成：主页头部从与标签相邻的 DOM 指标项读取“粉丝”“获赞”，概览账号表增加“获赞量”。

- 已完成：主页首屏因置顶作品导致普通作品不足时，采集器会有限次数滚动加载后续卡片，优先补足用户设置的非置顶作品数量。
